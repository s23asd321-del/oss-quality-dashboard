# Overview

## Background

Many small open source repositories are missing basic project quality signals: README details, license files, tests, docs, community files, CI, and clear safety boundaries. `oss-quality-dashboard` provides a local-first dashboard for checking those signals across explicitly selected local repositories.

## Target Users

- Developers preparing a repository for public sharing.
- Maintainers who want a lightweight local checklist.
- Portfolio builders who want to show backend, database, frontend, testing, Docker, CI, and documentation skills in one bounded project.

## Non-Target Users

- Teams needing enterprise compliance tooling.
- Users needing legal review, security audit, vulnerability scanning, or real secret scanning.
- Users needing remote GitHub organization inventory or cloud dashboards.

## Use Cases

- Add a local project path.
- Run a read-only scan.
- Review score, severity counts, findings, and recommendations.
- Download a Markdown report for private review.
- Use sample repositories to understand expected findings.
